# Shivam Sharma | Data Analyst Portfolio

This site runs **only on GitHub**: source in GitHub, automatic builds with GitHub Actions, hosting on GitHub Pages. **No Sanity, no Netlify, no external database, and no server login.** The site uses original static HTML/CSS generated by a small, dependency-free Node.js script. No command-line tools are required for everyday editing.

## First-time publishing: three clicks

1. Open the [repository settings](https://github.com/forevershivam/shivam-portfolio/settings/pages).
2. Under **Build and deployment**, choose **Source: GitHub Actions**. (Do not choose Deploy from a branch.)
3. Open the [Actions tab](https://github.com/forevershivam/shivam-portfolio/actions/workflows/pages.yml), open **Publish portfolio to GitHub Pages**, click **Run workflow**, then run on `main` if it has not started automatically.

After a successful deployment, the site will be available at:

**https://forevershivam.github.io/shivam-portfolio/**

If your repository is private and you use GitHub Free, make it public under **Settings > General > Danger Zone > Change repository visibility**, after reviewing the files. GitHub Pages on the Free plan needs a public repository. GitHub's repository settings control who can edit the source; anyone can view the public site.

The site is not considered launched until the deployment succeeds, pages and links have been reviewed on mobile and desktop, and the Privacy and Terms wording has been reviewed.

## How to update the website, without coding

GitHub itself is your editing area. Sign in to your GitHub account, open the file, click the **pencil** (Edit this file), change the **text between quotation marks**, then press **Commit changes**. GitHub Actions automatically rebuilds your website after each change. Do not delete the commas, quotation marks, or curly braces. The GitHub editor shows any JSON syntax problem before a successful build; if the build fails, look at the Actions log and use GitHub's Revert option or restore the previous file. Your account is the only account with write access unless you invite someone else.

| I want to… | Where to do it |
|---|---|
| Change home hero, skills, About, Contact, education and legal text | [`content/site.json`](content/site.json) |
| Switch among four themes | [`content/site.json`](content/site.json), change `"theme": "teal"` to `"mocha"`, `"champagne"` or `"slate"` |

### Add a project

1. Open [`content/projects.json`](content/projects.json) and click the pencil.
2. Copy the object from [`content/project-template.json`](content/project-template.json) into the `projects` array. For a single project, it looks like `"projects": [ { ...project fields... } ]`; for more projects, separate objects with commas.
3. Replace the placeholders with **real** project details: `title`, `slug` (lowercase hyphenated URL name), `summary`, `problem`, `dataSource`, `tools`, `steps`, `findings`, `workLink`, `screenshots` and `order`.
4. Keep `"published": false` until the case study is complete. Set it to `true` to display it on the public Projects page and automatically generate `/projects/<slug>/` on the next successful GitHub Actions run.
5. Click **Commit changes**. Project pages are created by GitHub Actions without new code.

To **delete** a project, remove its complete object from `content/projects.json`. To **reorder** projects, set each one's numeric `order` value (1 first, 2 second). To **hide** one, set `published` to `false`.

### Update a photo or resume

1. In the repository, open **Add file > Upload files**.
2. Upload a real image or PDF into the existing `assets` folder. If GitHub's upload UI opens at the root, open `assets` first and upload from there.
3. Commit the new file. In `content/site.json` change `portrait` to `assets/your-photo.jpg`, and `resume` to `assets/your-resume.pdf`. Leave the fields empty until you have real assets.
4. Use descriptive `portraitAlt` text and screenshot `alt` text. Do not upload private information.

### Custom domain, if you buy one later

In **Settings > Pages > Custom domain**, enter your real domain, and set the DNS records supplied in GitHub's [custom domain guide](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site). Update `siteUrl` in `content/site.json` to the final HTTPS domain URL ending in `/` and commit. Enable **Enforce HTTPS** after GitHub has issued the certificate. Do not enter a fictional domain.

## Important limits, read before using

- **No `/admin` login is available.** GitHub Pages is static hosting. GitHub's authenticated website editor replaces the separate CMS. A private admin interface with secure GitHub login, upload forms and instant server-side updates cannot be implemented using GitHub Pages alone.
- Public visitors cannot edit website data, but they can see the website. GitHub determines source write access.
- **Content updates require a commit**, and GitHub Actions takes some time to publish them. It is not an instant live CMS.
- All text and theme settings are editable via GitHub's file editor, but changing page layouts and adding new features requires editing HTML/CSS in `scripts/build.mjs` or `assets/styles.css`.
- GitHub Pages is for static websites, not a database, private authenticated admin dashboard, or contact form backend. Contact uses a working `mailto:` email link instead of a form.
- **No fake projects** are included. Projects show "Project case studies will be added here" until you publish one. Draft projects are never rendered.
- For legal safety, review and adjust the Privacy Policy and Terms to your actual usage and relevant Indian law before treating them as final.
- Do not put password, tokens, private documents or personal secrets into `content/` or `assets/`. This repository is public.

## Technical details

- Source content: `content/site.json`, `content/projects.json`
- Static template and build: `scripts/build.mjs`, using standard Node 22, no npm dependencies.
- Styles and icons: `assets/`
- GitHub-only deployment: `.github/workflows/pages.yml`, creates files in `dist/` and deploys to GitHub Pages.
- SEO: canonical URLs, unique titles and descriptions, social tags, `sitemap.xml`, `robots.txt`, favicon variants.
- Accessible design: semantic landmarks, focus indicators, responsive CSS down to 360 px, reduced-motion support.
- Design themes: `teal` (off-white/charcoal/dark teal), `mocha` (mocha/champagne/amber), `champagne` (champagne/cocoa), `slate` (ink/sand/mineral teal).
